# Skill: Autonomous Phase-by-Phase Stacked Workflow

Run feature implementation autonomously using Claude, phase-by-phase, creating stacked branches and automatically submitting Pull Requests for each completed phase.

## Usage

```bash
/workflow [max_iterations]
```

## What it does

1. **Detects Environment**: Auto-detects current feature branch (format `PM-NNN/slug`).
2. **Finds Stack Position**: For each phase, reads that phase's OWN branch's copy of `tasks.md` (via `git show`) to see if it's fully checked off, and resumes from the last completed phase's branch. If starting fresh, starts from the main feature branch.
3. **Iterates Phase-by-Phase**: For the next phase with pending tasks:
   - Creates a stacked branch: `PM-NNN/phase-X-slug` (ex: `PM-001/phase-1-foundation`) based on the previous phase's branch.
   - Spawns Claude with the **backend-engineer agent persona** and passes **all pending tasks** for the current phase.
   - **Static system prompt, built once per run.sh invocation (not per phase):** `.claude/agents/backend-engineer.md` plus the full contents of `docs/architecture/13-backend-development-checklist.md` are concatenated into one `--append-system-prompt` string. It's byte-identical across every phase, so after phase 1 pays full price, phases 2..N hit Anthropic's prompt cache for it instead of the agent spending tool calls re-reading the checklist or exploring other modules for patterns.
   - **Phase-scoped prompt (piped via stdin):** instead of the whole feature's `tasks.md`, the per-phase prompt reads only `docs/features/PM-NNN-*/phases/phase-N-slug/{tasks.md,test-cases.md,blueprint.md}` — that phase's tasks, its test cases, and the full Blueprints section (exact signatures/decision tables from `plan.md`, same content in every phase so it's cache-friendly too). Falls back to the full `tasks.md` for features created before `/feature-task` generated phase folders. Also includes a compact "What Prior Phases Exported" block pulled from `progress.txt` and an explicit "don't re-read the checklist, don't explore" instruction — see `run.sh` for the exact text.
   - Claude works autonomously to implement each task sequentially using a TDD cycle (write failing test -> implement -> pass tests -> mark done -> commit via `/commit` skill). It marks its own progress with `bash .claude/skills/workflow/mark-done.sh $PM_NUM <ID>` — once for the task's own `B-NNN` id, once per `T-NNN` test case it satisfied — instead of hand-editing `tasks.md`/`test-cases.md`. The script checks the box in both the flat file and its phase slice and stages the change, so it rides along in that task's own commit rather than a separate bulk edit.
   - Once all tasks in the phase are completed, Claude ends its reply with `✅ PHASE COMPLETE` followed by an `## Exports` section listing the exact signatures it added. `run.sh` extracts that block and appends it to `progress.txt` under this phase's entry — since `progress.txt` is committed on the phase branch and phases stack, the next phase's prompt already has every prior phase's exports without re-reading source files.
   - `run.sh` verifies every pending task actually got marked via `mark-done.sh` (rather than trusting the "PHASE COMPLETE" text alone) — anything the agent forgot is marked as a fallback but flagged loudly, since a forgotten mark is worth checking `phase-N-output.log` for. Progress is logged to `progress.txt` **as a commit on the phase branch itself** — never on the feature branch.
   - Pushes the phase branch to origin (with retries — see `push_with_retry` in `run.sh`).
   - Automatically creates a stacked Pull Request targeting the previous phase branch using `gh pr create`.
   - Updates the base pointer to this phase branch and stays checked out on it — the next phase branches directly off it.
4. **Completion**: Repeats until all phases are done or max iterations reached.

## Requirements

- Must be on a feature branch: `PM-NNN/slug`.
- **Definition of Ready (DoR)**: A `plan.md` file must exist in the feature directory.
- `tasks.md` must exist in `docs/features/PM-NNN-*/` structured with `## Phase N:` headings.
- Each task format: `- [ ] B-NNN: Description`.
- `phases/phase-N-slug/{tasks.md,test-cases.md,blueprint.md}` should exist (generated by `/feature-task`) — falls back to the full `tasks.md` per-phase if missing, but re-running `/feature-task` is recommended for the token savings.
- Claude Code CLI available.
- GitHub CLI (`gh`) authenticated and configured, with a remote for PR creation to work (the workflow still runs and marks tasks done locally without it — only the push/PR steps are best-effort).
- Git with remotes configured.

## Output

- Stacked branches: `PM-NNN/phase-1-slug`, `PM-NNN/phase-2-slug`, etc.
- Stacked PRs on GitHub (each phase targeting the previous phase branch), plus one top-level PR (`main <- PM-NNN/slug`).
- `tasks.md` and `test-cases.md` updated with `[x]` marks (via `mark-done.sh`, agent-driven, one call per finished item), and `progress.txt` updated with timestamps + each phase's `Exports` — all as commits **on each phase branch**, not on the feature branch.

## Branch Strategy

- **Feature branch** (`PM-NNN/slug`) — coordinates the workflow but is never edited by it directly. Its own `tasks.md` stays as originally written until the phase PRs actually merge into it; the workflow only reads phase branches' copies of `tasks.md` to know what's done.
- **Phase branches** (`PM-NNN/phase-X-slug`) — stacked branches that contain the implementation of each phase, sequentially branched off each other. Its tasks are marked `[x]` in `tasks.md` on the phase branch itself.
- **Stacked Pull Requests** — opened on GitHub targeting the branch of the preceding phase. Landing the stack (merging phase PRs bottom-up so the code actually reaches the feature branch, then `main`) is a separate, reviewed step this script does not perform automatically.
- **Top-level PR** (`main <- PM-NNN/slug`) — created idempotently on every run if it doesn't already exist.

## Stop Behavior

Loop stops when:

- All phases are complete (success).
- Max iterations reached (default: 10).
- Claude CLI fails or user interrupts (Ctrl+C).
